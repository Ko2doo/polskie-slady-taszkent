# Repository layout (the root, not just `src/`)

`src/` is where almost all day-to-day work happens and is mapped in detail in
`harness/architecture.md`. This file maps **everything else at the repo root**: what each
directory/file is for, whether it's generated or hand-maintained, and whether the agent is
expected to touch it.

## The tree

Every git-tracked entry at the repo root; a directory is expanded only where its
subdirectories matter, and then **all** of its subdirectories are listed (files inside are
listed only when they are a key entry point). `src/repositoryTree.test.js` checks this
against the working tree minus git-ignored files (`git ls-files --cached --others
--exclude-standard`), so an added, renamed or removed root entry — or a subdirectory of an
expanded directory — fails the suite until the tree is updated, committed or not. Ignored/generated entries
(`node_modules/`, `dist/`, `coverage/`, …) are not in git and so not in the tree — see the
end of this file. `🚫` marks what the agent never runs or edits without an explicit request.

## Source of the app

- `src/` — the app itself. See `harness/architecture.md`.
- `index.html` — Vite entry; mounts `src/main.js` into `#app`. Viewport is locked
  (`user-scalable=no`, `viewport-fit=cover`) on purpose — this is a native-feeling app, not a
  zoomable web page.
- `public/` — static assets copied as-is into `dist/` and served from `/`. Contains the
  offline map data (`public/map/`), map glyphs (`public/fonts/map/`), the UI font
  (`public/fonts/Roboto-*.ttf`), and historical-place preview images (`public/previews/
  <articleId>.webp`). See `.claude/rules/map-data-pipeline.md` for what's in `public/map/` and how
  it's produced. **Note:** `.prettierignore` excludes `public/` — large generated JSON lives
  there; never reformat it.

## Build and tooling config

- `package.json` / `package-lock.json` — scripts and dependencies. Never edit dependencies
  without the approval flow in `.claude/rules/dependencies.md`. Key scripts:
  - `dev` / `build` / `preview` — Vite.
  - `build:sync:android`, `build:copy:android` — `npx cap sync|copy android` (copies `dist/`
    into the native project).
  - `build:debugApp:android` / `build:releaseApp:android` / `build:all` — Gradle builds.
  - `release` — `scripts/release.mjs`. **The agent never runs this** (see
    `harness/git-workflow.md`).
  - `test` / `test:watch` / `test:coverage` — Vitest, see `harness/testing.md`.
  - `lint` / `lint:fix` — ESLint; `format` / `format:check` — Prettier. `prebuild` runs
    `lint` + `format:check`, so every `npm run build` (and `build:all`) stops on a lint error
    or unformatted code — a style guarantee that doesn't depend on anyone's editor setup.
  - `map:download-sprites` — see `.claude/rules/map-data-pipeline.md`.
- `vite.config.js` — Svelte + `@tailwindcss/vite` plugins, the `@` → `src/` alias, and two
  compile-time globals: `__APP_VERSION__` (from `package.json`) and `__APP_NAME__` (from
  `capacitor.config.json`). A test config must reproduce the alias and these globals.
- `vitest.config.js` — test config, built on top of `vite.config.js`. See
  `harness/testing.md`.
- `svelte.config.js` — `vitePreprocess()` only.
- `jsconfig.json` — editor/type hints: `@/*` path alias, `checkJs: false` (JSDoc types are
  documentation, not enforced).
- `tailwind.config.js` — Tailwind 4 JS config, loaded from `src/App.css` via `@config`;
  remaps `black`/`white`. See `.claude/rules/styling.md`.
- `eslint.config.js` — ESLint flat config (`npm run lint`, `npm run lint:fix`); what each rule
  enforces is in `harness/code-style.md` → "Linting and formatting".
- `.prettierrc` (semicolons, single quotes in `.js`, double in `.svelte`,
  `prettier-plugin-svelte`), `.prettierignore`, `.editorconfig` (LF, UTF-8, final newline,
  2-space indent, 120-char lines — Prettier reads its width from here). `npm run format` /
  `npm run format:check`.
- `.nvmrc` — Node version (`v24.x`); `package.json` `engines` requires Node ≥ 24, npm ≥ 11.
- `capacitor.config.json` — `appId`, `appName` (also used as `__APP_NAME__`), `webDir:
  dist`, SplashScreen plugin config (`launchAutoHide: false` — the app hides it itself once
  ready).

## Native projects

- `android/` — the Capacitor Android project (Gradle). Mostly generated by Capacitor;
  hand-edited parts are `app/build.gradle` (`versionName`/`versionCode`, bumped by the
  release script), the manifest (permissions), and resources. `app/src/main/assets/public`
  is a build copy of `dist/` and is git-ignored — never edit it.
- `ios/` — the Capacitor iOS project (Xcode). `App/App.xcodeproj/project.pbxproj` carries
  `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` (also bumped by the release script).
  `App/App/public` is git-ignored, same as on Android.
- A change that adds a Capacitor plugin or a native permission needs `npx cap sync` and
  usually a manifest / `Info.plist` edit — say so in the step summary; the agent doesn't run
  native builds.
- `resources/icon.png` — source for `npm run assets:generate:android`
  (`@capacitor/assets`), which generates launcher icons/splashes into `android/`.

## Data and maintenance scripts (`scripts/`)

**Hands off:** the agent doesn't modify, refactor, "clean up", delete, or run anything in
`scripts/` unless explicitly asked — that includes fixing a typo, an outdated path, or a
script that looks unused (`generateMaplibreBaseStyle.mjs`). If something there looks wrong,
mention it; don't touch it.

- `scripts/release.mjs` — the release flow. **Never run by the agent** (a dry run only when
  asked); how it works is in `CONTRIBUTING.md` → "Releases" — keep that in sync with the
  script. It builds `CHANGELOG.md` from commit-subject prefixes (`harness/git-workflow.md`).
- `scripts/overpass/`, `scripts/navigationGraph/`, `scripts/downloadProtomapsSprites.mjs`,
  `scripts/generateMaplibreBaseStyle.mjs` — the offline map/navigation data pipeline. See
  `.claude/rules/map-data-pipeline.md`.

## Store listings and marketing (not app code)

- `appstore/` — App Store Connect tooling in Python (`asc.py` — minimal API client with a
  JWT signer; `submit.py` — the submission driver; `metadata.py` — listing copy per locale)
  plus `metadata/` text files and `screenshots/`. `appstore/metadata/review_information/` is
  git-ignored (reviewer contact PII). **Never run these scripts** — `submit.py submit` sends
  the app to Apple for review; this is the same class of action as a release.
- `Banners/` — store marketing images (per language). Not used by the app.
- `PRIVACY.md` — the public privacy policy linked from the stores. It promises the app
  collects **no** data and that location never leaves the device. Any feature that would
  change that (a network call carrying user data, analytics, crash reporting) contradicts
  a published legal document — stop and ask.
- `BUGS.md` — temporary bug log kept between agent sessions; created and deleted per
  `harness/testing.md` → "Bug log". Not loaded into context by default.
- `CHANGELOG.md` — generated by `scripts/release.mjs`; don't hand-edit entries.
- `README.md`, `LICENSE` (MIT).
- `CONTRIBUTING.md` — the rules for anyone contributing, including the merge gate; the
  human-facing summary of the harness (see `harness/git-workflow.md`).

## GitHub (`.github/`)

- `workflows/ci.yml` — CI on push/PR to `features`/`master`: `npm ci`, `npm run lint`,
  `npm run format:check`, `npm test`, `npm run build` (Node from `.nvmrc`), in job
  `test-and-build` — the name branch protection requires, don't rename it. It's the automated
  part of the merge gate; keep it in sync with the scripts. Making CI a required check is a GitHub repo
  setting (branch protection), not something in the repo.
- `pull_request_template.md` — the merge-gate checklist every PR shows.

## Agent / editor config

- `CLAUDE.md`, `harness/` (always loaded), `.claude/rules/` (path-scoped) — this harness,
  see `.claude/rules/maintaining-this-harness.md`. `AGENTS.md` — a short pointer to them for
  agents that look for that file instead of `CLAUDE.md` (Codex, Cursor and others); the
  rules themselves are never duplicated there.
- `.claude/settings.json` — telemetry opt-outs (`CONTRIBUTING.md` → "Claude Code privacy
  settings") and the permission deny list backing `harness/git-workflow.md` → "What the
  agent never does".
- `.vscode/extensions.json` (tracked), `.idea/` (ignored) — editor config, leave alone.

## Generated / ignored — never edit by hand

`node_modules/`, `dist/`, `coverage/`, `android/app/src/main/assets/public`, `ios/App/App/public`,
`*.patch` (git-ignored), `scripts/navigationGraph/dist/` (intermediate pipeline output).
